## 1. Summary

SEION AutoPart AI is a workbench for **Tier-2 automotive suppliers in India**. It turns a foreign-spec customer BOM (DIN / ISO / EN parts and materials) into a **customer-approvable localization proposal**:

1. Every line is matched to its **Indian Standard (IS)** equivalent from a curated, plant-editable standards table.
2. Every swap is **checked against engineering rules** (property class, tensile and yield strength, hardness, thread fit, coating).
3. Domestic suppliers are compared on cost and lead time, with **BIS licence, IATF 16949 and ISO 9001 status**.
4. **RFQs** are drafted and quotes tracked.
5. The plant **exports a proposal pack** for the customer's PPAP / change-approval process and tracks approval through to realised savings.

It runs as a self-contained app on a plant PC or intranet server, with no cloud services, accounts or API keys required.

## 2. Problem statements (from market research)

| # | Problem | Evidence | Consequence for the product |
| --- | --- | --- | --- |
| P1 | Foreign-spec parts must now be sourced as BIS-certified IS parts | Fastener QCO enforced from 20 Mar 2025 (large firms and imports) through 20 Sep 2025 (micro firms) | Core job: **spec → IS equivalent**, with the supplier's BIS licence visible |
| P2 | Cross-referencing is manual, slow and inconsistent | Engineers hunt catalogs line by line; generic LLMs hallucinate equivalences | Deterministic matching from a **curated table**, never generated by AI |
| P3 | A swap on an approved part needs customer approval (PPAP) | IATF 16949 / AIAG PPAP change rules | Track **plant decision** and **customer approval** separately; export a proposal pack |
| P4 | The domestic part is not always cheaper | Chinese parts often land 20–30% cheaper; margins have fallen to 10.5–11% | Show **honest per-unit, per-vehicle and annual** cost deltas, including negative ones |
| P5 | Equivalences carry engineering caveats (grade, coating, hardness) | e.g. electro-zinc is not a zinc-flake substitute for underbody parts | A **rules-based validation** checklist per alternative, with explicit reasons |
| P6 | Supplier capability and pricing live in people's heads | No neutral, plant-owned supplier database | **Supplier directory and price list** that RFQ quotes keep up to date |
| P7 | Savings claims aren't credible until realised | Research found the old ROI claims unsupported | Report **proposed vs customer-approved** annual savings separately |
| P8 | MSMEs won't adopt heavy software | Price-sensitive, little IT support | **Zero-config** install; works offline; plain CSV, XLSX and PDF inputs |

## 3. Users

| Persona | Goal | Main screens |
| --- | --- | --- |
| **Procurement engineer** (primary) | Localize a customer BOM quickly; get quotes | BOMs, BOM detail, RFQs, Suppliers |
| **Quality / SQA engineer** | Make sure no swap breaks spec; prepare the PPAP submission | BOM detail (validation), Proposal pack, Standards |
| **Plant head / commercial** | See savings that are proposed and approved | Dashboard, Savings |

Single-plant deployment. No login (per product decision, §7). Each person enters their name once on the Settings page, and it is used to sign RFQs and proposals.

## 4. User stories and acceptance criteria

### 4.1 Setup
- **US-1** As a plant user I set company name, plant location / cluster, contact person, email, phone, GSTIN and a default annual vehicle volume, so RFQs and proposals are filled in correctly.
  - AC: The Settings page saves all fields. RFQ and proposal text use them. The app works with empty settings, using neutral defaults.

### 4.2 BOM intake
- **US-2** I upload an `.xlsx`, `.csv` or text-based `.pdf` BOM up to 10 MB, and its lines are extracted without any AI key.
  - AC: Header synonyms are recognised (part no / description / spec / standard / qty / rate / supplier / material / category, …).
  - AC: Quantities and costs like `4 nos` or `₹1,250.50` are parsed.
  - AC: When there is no spec column, a DIN/ISO/IS/EN/JIS/SAE reference in the description is used as the spec.
  - AC: Unsupported files (`.xls`, STEP, scanned PDF) fail with a specific, actionable message.
- **US-3** If headers can't be recognised and a `GROQ_API_KEY` is configured, AI extraction is used as a fallback. Without a key, I'm told how to fix the file and pointed to the template.
- **US-4** I can download a **BOM template** and load a **sample BOM** to try the workflow end to end.
- **US-5** For each BOM I can set the title, customer, vehicle platform and **annual volume**, which drives the annual savings figures.
- **US-6** I can **edit a line** (part no, name, spec, qty, unit cost, category). It is re-matched immediately, so I can fix a typo'd spec on a "Needs review" line.
- **US-7** I can **re-match** a whole BOM after the standards table or prices change, without losing decisions on lines whose match didn't change.
- **US-8** I can delete a BOM.

### 4.3 Matching and alternatives
- **US-9** Each line shows its match status (Matched / Needs review), the recognised source standard, the target IS standard and the equivalence level (Equivalent / Near) with notes.
- **US-10** Matched lines list up to 3 supplier offers for the IS spec, cheapest first. They show unit cost, savings % (negative shown in red), per-vehicle and annual delta, lead time, and BIS / IATF / ISO status.
- **US-11** When no supplier has a price for the IS spec, the line still gets an IS alternative marked "No quote yet", with an RFQ call to action.

### 4.4 Engineering validation
- **US-12** Every alternative gets an automatic **rules-based validation**: part family, property class, tensile and yield strength, hardness, thread fit, equivalence level and coating keywords. Each check reads Pass / Warn / Fail with a reason, and there is an overall recommendation (Safe to switch / Requires testing / Not recommended).
  - AC: Results are reproducible, the same inputs always give the same output, and no AI is involved.
  - AC: A zinc-flake coating requirement in the source spec produces a warning recommending IS 16647, not electro-zinc.

### 4.5 Decisions and customer approval
- **US-13** I can **accept** one alternative per line (any others on that line are set to rejected) or reject alternatives. I can **reset** a decision.
- **US-14** For an accepted alternative I track the **customer approval status**: Not submitted → Submitted → Approved / Rejected, with a customer reference (ECN / PPAP no.) and notes.
- **US-15** I can open a **printable proposal pack** for the BOM. It contains a cover, a summary of lines and savings, a per-line equivalence, validation and supplier table, the PPAP note and a sign-off block, and prints cleanly to PDF.
- **US-16** I can export the proposal as **CSV**.

### 4.6 Suppliers and RFQs
- **US-17** I can add, edit and delete suppliers: name, hub, state, contact, email, phone, BIS licence no., IATF 16949, ISO 9001, rating and lead time.
- **US-18** I can manage each supplier's **price list** per IS spec (unit cost, lead time, valid-until).
- **US-19** From any alternative I can **create an RFQ** to its supplier or any other supplier. The email draft is generated from a template and includes:
  - the spec with source-standard reference and annual quantity (qty × annual volume)
  - a target price
  - requests for the BIS licence, mill test certificates (MTC), PPAP level and lead time
  - the signature from Settings
- **US-20** I can copy the RFQ, open it in my mail client (`mailto:`), mark it **Sent**, and record a **Quote** (unit price, lead time, valid until). The quote **updates the supplier price list** and the alternative's cost, so savings recalculate.
- **US-21** An RFQ list shows every RFQ with status, filterable as Open (draft / sent) or All.

### 4.7 Standards library
- **US-22** I can search the standards table and see specs (body, code, family, mechanical properties, notes) and equivalences.
- **US-23** I can **add a spec** with its mechanical properties and source reference, **add an equivalence** between two specs (Equivalent / Near / Not equivalent) with notes, and delete either. Changes take effect on the next upload or re-match.
- Seeded rows are labelled "Seed (indicative)", and plant-added rows "Plant-verified".

### 4.8 Insight
- **US-24** The dashboard shows:
  - BOMs in total, lines, IS match rate and lines needing review
  - proposed annual savings, customer-approved annual savings and open RFQs
  - recent BOMs
- **US-25** The Savings page shows annual savings by month of decision (proposed vs approved) and by category, plus a per-BOM table.
- **US-26** Each BOM shows an **activity log**: uploaded, re-matched, line edited, accepted / rejected, customer status changed and RFQ events.

## 5. Non-functional requirements

| Area | Requirement |
| --- | --- |
| Install | `pnpm install && pnpm dev` on Node ≥ 22.13 with no other services. Docker image with a data volume for servers. |
| Data | One SQLite file (`./data/seion.db`, overridable via `DATABASE_PATH`). Schema migrates automatically. The seed catalog loads on first run. |
| Privacy | BOMs never leave the machine unless the optional Groq fallback is enabled. |
| Performance | A 500-line CSV processes in under 3 s on a laptop. Pages render server-side. |
| Reliability | Processing is transactional: a failed parse leaves the BOM `FAILED` with a message and the file stored for re-processing. |
| Accessibility | Labelled inputs, keyboard-reachable actions, readable at phone width with no horizontal page scroll. |
| Integrity | Engineering facts come only from the standards table. AI is limited to optional row extraction. |
| Testability | Pure domain modules plus repository tests against in-memory SQLite. |

## 6. Success metrics (pilot)

- Time from upload to a reviewed proposal is **under 30 minutes** for a 100-line BOM.
- **At least 60% IS match rate** on fastener-heavy BOMs with the seed catalog; it rises as plants add equivalences.
- **At least 1 customer-approved substitution** per pilot plant within 90 days (the kill criterion from research).
- **At least 50%** of RFQs get a quote recorded.

## 7. Product decisions

| Decision | Rationale |
| --- | --- |
| **No login; single plant** | User request. MSMEs want zero setup. Deploy on a trusted LAN, or put a reverse proxy or VPN in front if exposure is needed. |
| **Embedded SQLite (`node:sqlite`)** | Zero external services and zero native build. Backups are a single file. |
| **Deterministic core; AI optional** | Research: credibility depends on facts from data. Removes the API-key dependency. |
| **No SMTP sending** | Avoids credential setup and deliverability problems. `mailto:` plus copy covers the workflow. |
| **Proposal pack as printable HTML** | Print-to-PDF works everywhere; no PDF library needed. |
| **Seed data clearly labelled indicative** | Seeded prices are illustrative; plants replace them through RFQ quotes. |

## 8. Out of scope (v1)

Multi-plant tenancy and SSO; ERP sync; CAD/STEP geometry; scanned-PDF OCR; live BIS licence lookup (the licence no. is entered manually); supplier portal; e-mail sending; landed-cost modelling for imports (users enter a landed unit cost).
